## 3. Header

- Brand `agent` + `log` (accent colour), mono, bold.
- Live dot (green, pulsing). It turns grey with tooltip "disconnected" if 2 consecutive polls fail, and goes back to green on recovery.
- Repo name and branch pill.
- Keyboard hint `j/k move`.
- Order toggle: **Newest first** (default) | **Story order** (oldest first). Persist in `localStorage` (wrap in try/catch).
- Filter input (260px). `/` focuses it. `Esc` inside it clears it.

## 4. Timeline (left)

- Items are grouped under sticky day headers: `Now` (working tree), `Today`, `Yesterday`, otherwise `Sat, 21 Nov 2026`.
- A vertical line runs through the dots (pseudo-element on each item, x=24px).
- **Item:** dot · subject (2-line clamp, weight 500) · meta row (mono 12px):
  `#<n>` (position counted from oldest = 1) · agent badge · relative time · `+ins −dels`.
- Dot styles: agent commit = accent ring; human = faint ring; `[auto]` = dashed faint
  ring with dim subject; working tree = green ring and green-tinted fill; selected = solid accent fill and a 2px accent left border.
- Badges: agent name (accent tint), `auto` (grey tint), `working tree` (green tint). Human commits get no badge.
- Working-tree pseudo-item: shown only when `dirty > 0`, labelled `Uncommitted changes (N files)`. It sits at the top in Newest order and the bottom in Story order.
- Filter matches subject, body, short hash, agent, and file paths of commits whose patch is already loaded.
- Empty states: no commits → "No commits yet. Ask your agent for a change and it will show up here." No filter matches → "No matches."

## 5. Detail (right), max-width 1200px, centred

- `h1` subject (21px, 600). Body below in dim pre-wrap. **Strip trailer lines**
  (`Co-Authored-By:`, `Agent:`, `Claude-Session:`, `Signed-off-by:`) from the displayed body.
- Meta row: `#n of N` · author (bold) · agent if any · local datetime (ISO in tooltip) ·
  short hash button (click → copy full hash, label shows "copied ✓" for 1.5 s) · `files · +a −d`.
- File chips: base name + `+a −d`. Clicking one expands that file card and smooth-scrolls to it.
- **File card:** sticky header containing a collapse caret (rotates), full path (ellipsis, full path in title),
  status pill (`added` green, `deleted` red, `renamed`, `modified`), `+a −d`, **View file** button
  (hidden for deleted and binary files). Cards with more than 400 changed lines start collapsed.
- **Diff table:** columns old line #, new line #, code.
  **Use `<colgroup><col style="width:52px"><col style="width:52px"><col></colgroup>`.** The prototype bug made the number columns huge.
  Rows: hunk header (`--hunk` bg, full width), `add` (green bg, `+` prefix),
  `del` (red bg, `−` prefix), `ctx`. Code wraps (`pre-wrap; word-break: break-all`).
  Number cells are `user-select:none`.
- Binary file → "Binary file". No hunks (pure rename or mode change) → "No content changes (renamed)".
- Truncated patch (`truncated: true`) → a banner at the top: "Diff truncated (very large commit)".
- Loading state: "Loading…" placeholder. Ignore stale responses if the selection changed meanwhile.

## 6. View-file modal

- Title `path @ <short hash | working tree>` and a Close button. `Esc` or a backdrop click closes it.
- Content shown as a numbered table (same colgroup approach, 2 columns). Binary → message.

## 7. Behaviour

- **Polling:** every 3 s, `GET /api/repo`. Only if `head` or `dirty` changed: refetch commits.
  If the selection still exists, keep it, and re-render the detail when it's `WORKING`.
  If it vanished, select the top item for the current order.
- On first load, select the top item for the current order.
- Patch cache: in memory, keyed by hash. Never cache `WORKING`.
- **Keyboard:** `j` next, `k` previous (in visible order, scrolls the item into view),
  `/` focus filter, `Esc` closes the modal or clears the filter. Ignore keys while typing in an input.
- URL hash `#<commitHash>` reflects the selection. Loading with a hash selects that commit (deep links).

## 8. diff.js contract (pure)

```js
export function parsePatch(text) → File[]
// File = { path, oldPath, status: 'added'|'deleted'|'renamed'|'modified', binary, add, del,
//          hunks: [{ header, lines: [{ type:'add'|'del'|'ctx', old:number|null, new:number|null, text }] }] }
```
It must handle: `new file mode`, `deleted file mode`, `rename from/to`, `similarity index`,
`Binary files … differ`, `\ No newline at end of file` (skip the line, don't count it),
`--- /dev/null` and `+++ /dev/null`, hunk headers without counts (`@@ -1 +1 @@`), and paths containing spaces.
