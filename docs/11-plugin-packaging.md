# 11: Plugin packaging, distribution and publishing

> Source of truth for formats: the Claude Code plugin docs at
> `https://code.claude.com/docs/en/plugins` (create, components, manifest reference,
> marketplace reference, publish). Formats change. Before starting M6, re-read the
> manifest reference and run `claude plugin validate`. If anything here disagrees with
> the docs or the validator, the docs win; record the change in `docs/DECISIONS.md`.

## 1. Repository = marketplace + plugin + Go source

One GitHub repo serves three roles:

- The **Go source** for the binary (`cmd/`, `internal/`, `web/`).
- The **plugin** (`plugin/`), the folder Claude Code copies into its cache on install.
- A **marketplace** (`.claude-plugin/marketplace.json` at the repo root), so people can
  install before (or without) the official directory listing.

A plugin can't reference files outside its own folder after install (the folder is
copied to a cache). So everything the plugin runs, including the binaries, must live under `plugin/`.

## 2. Plugin layout

```
plugin/
├── .claude-plugin/
│   └── plugin.json              # manifest (§3)
├── hooks/
│   └── hooks.json               # SessionStart + Stop (05-agent-integration.md §3)
├── skills/
│   ├── init/SKILL.md            # /agentlog:init
│   ├── ui/SKILL.md              # /agentlog:ui
│   ├── disable/SKILL.md         # /agentlog:disable
│   └── status/SKILL.md          # /agentlog:status
├── scripts/
│   ├── agentlog                 # POSIX sh launcher: picks the right binary (§4)
│   └── dist/                    # prebuilt binaries, generated by `make dist` (§5)
│       ├── agentlog-darwin-arm64
│       ├── agentlog-darwin-amd64
│       ├── agentlog-linux-amd64
│       ├── agentlog-linux-arm64
│       └── agentlog-windows-amd64.exe
├── assets/
│   └── icon.png                 # 512×512 directory icon
├── README.md                    # plugin-facing docs (shown on GitHub; keep short)
└── LICENSE
```

Rules:

- **No top-level `plugin/bin/` directory.** Files there would land on Claude's PATH, but
  claude.ai and Cowork refuse to install a plugin that has one. Binaries live in `scripts/dist/`.
- **Use `skills/`, not `commands/`.** The docs recommend skills for new plugins. Each skill
  is invoked as `/agentlog:<skill-name>`.
- **No `CLAUDE.md` in the plugin root.** It isn't loaded, and the validator warns about it.
  Context goes through skills and the SessionStart hook.

## 3. `plugin/.claude-plugin/plugin.json`

```json
{
  "name": "agentlog",
  "displayName": "agentlog",
  "version": "0.1.0",
  "description": "Makes AI coding agents commit every change locally with clear messages, and shows the history as a clickable timeline with diffs. Nothing is pushed.",
  "author": { "name": "<your name>", "url": "https://github.com/<you>" },
  "homepage": "https://github.com/<you>/agentlog",
  "repository": "https://github.com/<you>/agentlog",
  "license": "MIT",
  "keywords": ["git", "commits", "history", "review", "diff", "local", "timeline"],
  "icon": "./assets/icon.png",
  "documentationUrl": "https://github.com/<you>/agentlog#readme",
  "supportUrl": "https://github.com/<you>/agentlog/issues",
  "userConfig": {
    "enforce_everywhere": {
      "type": "boolean",
      "title": "Enforce in every git repo",
      "description": "If on, agentlog enforces commits in every git repo. If off (default), only in repos where you ran /agentlog:init.",
      "default": false
    },
    "ui_port": {
      "type": "number",
      "title": "Timeline UI port",
      "description": "Local port for the agentlog timeline UI",
      "default": 7777, "min": 1024, "max": 65535
    }
  }
}
```

Notes:
- `name` must be kebab-case and must not start with `claude-` or `anthropic-` (the validator rejects those). `agentlog` is fine.
- `version` pins users to that version until it changes. Bump it on every release (§7).
- The directory-listing fields (`icon`, `documentationUrl`, `supportUrl`) are read by Anthropic's directory and ignored by Claude Code.

## 4. Launcher `plugin/scripts/agentlog` (POSIX sh)

```sh
#!/bin/sh
# Picks the prebuilt agentlog binary for this OS/arch and execs it.
DIR="$(cd "$(dirname "$0")" && pwd)"
os="$(uname -s | tr '[:upper:]' '[:lower:]')"; arch="$(uname -m)"
case "$os" in mingw*|msys*|cygwin*) os=windows ;; esac
case "$arch" in x86_64|amd64) arch=amd64 ;; arm64|aarch64) arch=arm64 ;; esac
bin="$DIR/dist/agentlog-$os-$arch"; [ "$os" = windows ] && bin="$bin.exe"
if [ ! -x "$bin" ]; then
  # Never break Claude: hooks must exit 0 even when no binary fits this platform.
  case "$1" in hook-*) cat >/dev/null; exit 0 ;; esac
  echo "agentlog: no prebuilt binary for $os-$arch. Install with: go install github.com/<you>/agentlog/cmd/agentlog@latest" >&2
  command -v agentlog >/dev/null 2>&1 && exec agentlog "$@"
  exit 1
fi
exec "$bin" "$@"
```

- It must be committed with the executable bit set (`git update-index --chmod=+x`).
- Windows: plugin hooks run through Git Bash when it's installed, and the launcher works there.
  PowerShell-only Windows is **unsupported in v1**. Document this in the README and `DECISIONS.md`.

## 5. Building the binaries (`make dist`)

```make
VERSION ?= $(shell git describe --tags --always --dirty)
LDFLAGS := -s -w -X main.version=$(VERSION)
PLATFORMS := darwin/arm64 darwin/amd64 linux/amd64 linux/arm64 windows/amd64
dist:
	@for p in $(PLATFORMS); do os=$${p%/*}; arch=$${p#*/}; ext=; [ $$os = windows ] && ext=.exe; \
	  CGO_ENABLED=0 GOOS=$$os GOARCH=$$arch go build -trimpath -ldflags "$(LDFLAGS)" \
	  -o plugin/scripts/dist/agentlog-$$os-$$arch$$ext ./cmd/agentlog || exit 1; done
dist-local:   # only the current platform, for development
	CGO_ENABLED=0 go build -trimpath -ldflags "$(LDFLAGS)" -o plugin/scripts/dist/agentlog-$$(go env GOOS)-$$(go env GOARCH) ./cmd/agentlog
```

**Where the binaries are committed:** keep `plugin/scripts/dist/` **gitignored on `main`**,
so the source history doesn't bloat. A GitHub Actions workflow (`.github/workflows/release.yml`)
runs on tag `v*`, does `make check dist`, and force-pushes the result to a `release` branch
(source + built `dist/`). Users install from the `release` branch (§6). Binaries are ~6 MB each.

## 6. Marketplace file (`.claude-plugin/marketplace.json` at the repo root)

```json
{
  "name": "agentlog",
  "description": "agentlog: local commit history for AI coding agents",
  "owner": { "name": "<your name>" },
  "plugins": [
    {
      "name": "agentlog",
      "source": { "source": "git-subdir", "url": "<you>/agentlog", "path": "plugin", "ref": "release" },
      "description": "Force agents to commit locally with clear messages; browse the history as a timeline."
    }
  ]
}
```

- The entry `name` must equal the manifest `name` (`agentlog`), otherwise installs fail with "not found".
- Don't use reserved marketplace names (`claude-plugins-official`, `claude-code-plugins`, `anthropic-plugins`, …).
- Check that `git-subdir` accepts `ref` in the current marketplace reference. If it doesn't, use a `github` source on a separate `agentlog-plugin` repo that CI pushes to, and record the choice.

Users install with:

```
/plugin marketplace add <you>/agentlog
/plugin install agentlog@agentlog
```

## 7. Skills

Each `SKILL.md` has frontmatter (`name`, `description`) and a body of instructions Claude
follows. `${CLAUDE_PLUGIN_ROOT}` is substituted inline in skill bodies. (It is **not** an env
var in Claude's Bash tool, so always write it literally in the Markdown.) Keep bodies short and imperative.

**`skills/init/SKILL.md`**
```markdown
---
name: init
description: Enable agentlog in the current project so every change Claude makes is committed locally with a clear message. Use when the user asks to set up or enable agentlog.
---
Run this in the project root with the Bash tool:

"${CLAUDE_PLUGIN_ROOT}/scripts/agentlog" init "$CLAUDE_PROJECT_DIR"

Then tell the user in 2–3 sentences what changed (local git repo if new, baseline commit,
commit rules in AGENTS.md, enforcement on for this repo) and that they can open the history with /agentlog:ui.
If the command fails, show the error and stop. Never push.
```
(If `$CLAUDE_PROJECT_DIR` isn't set in the Bash tool environment, use `.`. Verify this during M6.)

**`skills/ui/SKILL.md`**: run `"${CLAUDE_PLUGIN_ROOT}/scripts/agentlog" ui --detach .`, which
starts the server in the background (or reuses a running one) and prints the URL. Reply with
the URL only. With "stop" as the argument, run `… ui --stop .`.

**`skills/disable/SKILL.md`**: run `… disable .` and confirm that commits were left untouched.

**`skills/status/SKILL.md`**: run `… status .` and summarise: enabled or not, number of commits
by agent vs human vs auto since the baseline, uncommitted file count, and the UI URL if it's running.

## 8. Local development loop

```bash
make dist-local
claude plugin validate ./plugin          # must end with "Validation passed"
claude plugin validate .                 # validates the marketplace file
claude --plugin-dir ./plugin             # run Claude Code with the plugin loaded in place
# inside the session: /agentlog:init, then ask for a change, then /agentlog:ui
# after editing plugin files: /reload-plugins
```

To test the real install path: `claude plugin marketplace add ./` with a local copy whose
marketplace entry uses `"source": "./plugin"`, then `claude plugin install agentlog@agentlog`.
Don't commit that local variant.

Add `claude plugin validate --strict ./plugin` to CI when the `claude` CLI is available there.
Otherwise make it a manual release-checklist item.

## 9. Publishing

**a) Own marketplace (available immediately):** tag `v0.1.0` → CI builds the `release` branch →
users run the two commands in §6. Updates: bump `version` in `plugin.json`, tag, and users
update via `/plugin`.

**b) Anthropic's directory (listed in `/plugin` → Discover for everyone, and on claude.com/plugins):**
1. The repo must be public on GitHub, and the GitHub account must be connected on claude.ai (paid plan).
2. Go to `claude.ai/directory/manage` → **Submit new** → **Plugin bundle** → pick the repo
   and the `plugin` folder (on the `release` branch if the portal asks for a ref).
3. Fill the checklist. It reads the `plugin.json` listing fields, so make sure `icon`, `documentationUrl`
   and `supportUrl` are real. A privacy policy URL is recommended: state "agentlog sends no data anywhere;
   everything stays on your machine".
4. Anthropic reviews it against the Software Directory Terms and Policy. After publication, each new
   commit is picked up and scanned automatically.

**Release checklist (put it in `RELEASING.md`):**
- [ ] `make check e2e` green
- [ ] `version` bumped in `plugin/.claude-plugin/plugin.json` and in `main.version`
- [ ] `make dist` builds all 5 platforms; the launcher picks correctly on macOS and Linux
- [ ] `claude plugin validate --strict ./plugin` passes
- [ ] Fresh install from the marketplace on a clean machine: init → session → commits → UI
- [ ] Tag pushed, `release` branch updated by CI
